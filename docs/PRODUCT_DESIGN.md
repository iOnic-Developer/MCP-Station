# MCP Station · Public product workspace

## Scope and ownership

Implemented independently from stable main `9088321` on `redesign/public-product`.
The earlier redesign branch was not incorporated. This is an unreleased review branch, not a live
deployment. Application, branding/PWA, account backend and regression changes form one coherent pass.

Vanilla browser ES modules and the existing API wrapper remain the implementation platform.
No framework, dependencies, package changes or compilation/build pipeline were added.
`docs/ACCOUNT_INSTANCES.md` is the authoritative backend contract.

## Product decisions

This is a workflow redesign, not another skin. Everyday integration work is a full-page
workspace, with a stable account identity, endpoint, test and enable controls above its sections.
Credentials and access controls are never placed in a routine drawer or modal. Native dialogs
remain appropriate for destructive confirmations, clipboard fallback and mobile navigation.

Existing warm canvas, forest accents, semantic light/dark tokens, typography and local brand
assets are retained. The original Ribbon S brand and self-hosted font/PWA assets are documented in BRAND.md. CSS changes edit the
existing library rules, remove obsolete expanding-card rules and add one focused workspace
component section before the existing responsive rules, rather than stacking redesign overrides.
UI guidance follows the supplied accessibility, interaction, navigation and data-clarity priorities;
no local skill-search database result is claimed.

## Routes

| Route | Purpose |
| --- | --- |
| `#/overview` | Installed service/account readiness plus real tool usage |
| `#/integrations` | Equal-footprint searchable/filterable service library |
| `#/integrations/new` | Choose an installed service and name another account; advanced new-source creation |
| `#/integrations/:sourceId/settings?account=:instanceId` | Manifest-driven account settings and confirmed removal |
| `#/integrations/:sourceId/connect?account=:instanceId` | Endpoint, browser authorization, private tokens and authorized clients |
| `#/integrations/:sourceId/tools?account=:instanceId` | Searchable real capabilities, argument schemas, prompts and instructions |
| `#/integrations/:sourceId/code?account=:instanceId` | Advanced shared-source editor and scoped Assistant |
| `#/integrations/:sourceId/activity?account=:instanceId` | Selected account's actual tool activity |
| `#/integrations/:sourceId/add-account` | Account creation with the existing service preselected |
| `#/connect` | Connections list with account selectors, endpoints and usable quick actions |
| `#/assistant` | Station-wide Assistant |
| `#/settings` | Existing full-page station/provider settings |
| `#/backups` | Existing portability/backup/restore controls |

The tab is optional and defaults to Settings. Route segments are decoded defensively; malformed
segments, unsupported tabs, duplicate account query parameters and missing accounts get explicit
states rather than a crash or actions against an unintended account. Query strings use
`URLSearchParams`; source segments use URI encoding.

## Library and Connections

One service card per installed source, not one per account. Every card reserves the same space
for its name, two-line description, selected account, endpoint, three labeled upfront actions
(**Copy endpoint**, **Configure**, **Test**), last-test summary, **Open workspace**, and enable
switch. Cards do not expand and change height. Full test information is available in the workspace.
The search/filter state and library scroll position survive entering and leaving a workspace.

An in-memory map selects one account per source, shared by library, Connections and workspaces.
It contains account IDs only, is not written to local storage, and clears when unauthenticated.
Selections drive endpoint, status, settings, test, token and access requests. Opening a deep link
selects that account; canceling an unsaved account switch restores the selector and current form.

Connections is no longer just instructions: each source has an account selector, endpoint copy,
Configure, Test connection and Manage access. Results use the server's real message; failed or
unavailable tests are never styled or described as successful. Setup instructions follow the list.

## Guided account setup

Choose installed service → name account → save settings → test → copy endpoint. No slug field
or token terminology is required to create an account. The endpoint is generated by the server.
Creation uses `POST /api/mcps/:sourceId/instances` with only `{name}`. The new account is blank,
disabled and untested, without copying existing credentials. The resulting full-page workspace
shows settings supplied/needed and test passed/failed/not run from actual account metadata.
Copying an endpoint is not represented as a successful service test or completed client connection.
The enable switch is explicit; a successful test does not silently enable an account.

An advanced option retains creation of a new source/template for a service not installed yet.
That form renders inline on the creation page rather than opening a configuration overlay.

## Account boundaries and shared source

`accounts.js` owns account resolution, selector markup, workspace URLs, status and test feedback.
Account settings, test, capabilities, skill, token and client access use `instance.id`.
Editor/file/chat and source ZIP export deliberately use `source.id` even when another account
is selected. Code clearly states that edits affect **every account** of the service.

Settings removes an additional account only through
`DELETE /api/mcps/:sourceId/instances/:instanceId`, after confirmation explaining that its
credentials and access are removed while shared code and siblings remain. Default-source
removal retains the original trash behavior and warns that additional accounts must be removed
first; the backend enforces this boundary.

This is **not human multi-user hosting**. All accounts remain under the single station admin.
No human identities, ownership, tenant isolation, permissions or membership UI is claimed.

## Real usage, not decorative graphs

`usage.js` requests `GET /api/usage?days=7` or `days=30`, with `instanceId` for account Activity.
Overview shows tool calls, errors, success rate and average latency from returned totals, plus
an accessible SVG daily bar chart and equivalent date/calls/errors table. Only observed dates
are plotted; buckets are explicitly UTC. The rolling `since` time is displayed. Per-account totals
and recent account events use returned metadata, never generated samples.

Empty rates and latency are “No calls yet”, not fake 100% success or 0ms response. Empty history
has an explanatory state. A failed request replaces the summary with an error/retry control,
not fabricated zero metrics. The UI explains that setup tests, initialization and tool listings
are excluded, and that retention is bounded to 30 days / 5,000 events rather than a billing ledger.

## Preserved safety and accessibility

- Exact saved-secret sentinel `••••••`: blank keeps, replacement changes, explicit Clear removes.
  Secret controls are never prefilled. Successful saves clear plaintext from the inputs and update
  the local masked state, so saving a newly supplied secret again does not erase it.
- Editor Close, route/tab/account changes, browser history and file switching guard unsaved edits.
  Settings also guards unsaved changes. A browser unload warning covers dirty page surfaces.
- Leaving an editor dispatches `station:dispose`, disconnecting its observer/listeners and aborting
  its scoped chat stream. Leaving the station Assistant disposes its stream; conversation history
  remains in the existing browser store. Metadata refresh does not replace an open editor or
  one-time token display.
- Token rotation/revocation, OAuth-client revocation, source/account deletion and public skill
  sharing retain explicit confirmations. Skill-share text explains public seven-day readability
  and that a skill link does not grant endpoint access.
- Shared-source export, account skill download/share, broken-source repair and delete remain
  available in the workspace. Existing backups, restores and provider controls are retained.
- Page controls have visible labels, keyboard focus states and native selection/form semantics.
  Existing native dialogs retain focus trapping/return. Tool lists remain searchable; charts have
  textual labeling and a tabular alternative. The skip link focuses the main region without routing.
- `.quiet-note a` and `.guide-steps p a` have persistent underlines, not hover-only identification.
- Page layouts adapt to narrow screens and preserve mobile navigation/safe-area clearance.
  Light/dark semantic tokens and reduced-motion handling remain in use.

## Verification and limitations

Reproducible verification and screenshots are described in QA_WORKFLOWS.md. The isolated
Chromium suite passes 68/68 named workflow checks with 19 axe audits and no serious/critical
violations in those audits. It covers equal card sizes at 375/768/1440px, three configurations
sharing one source, selected-account actions, real activity and dirty-state route guards. PWA
checks pass 16/16. Account isolation and usage privacy/retention/restore regressions pass.

One-time token displays now guard route/tab/account changes and unload until explicitly copied,
acknowledged as securely stored, revoked or discarded. Signing out honors the same dirty-state
guard. Unknown request tool names are replaced with `(invalid)` in usage metadata. Restoring a
pre-analytics backup empties history rather than importing unrelated destination activity.

No live external provider, production deployment, native device, human multi-user permissions or
complete manual assistive-technology audit is claimed. Existing APIs/OAuth flows are covered by
protocol regression suites. Default-account JSON portability remains limited; use full backups
for additional accounts. Approved stable release aligns package and app versions at 2.7.0.
